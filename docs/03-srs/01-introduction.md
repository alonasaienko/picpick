# 1. Introduction

## 1.1 Document Purpose

Ця специфікація вимог (SRS) визначає призначення, межі та очікувану поведінку PicPick — вебсервісу для спільного відбору фото фотографом і клієнтом. Документ є основою для узгодження функціональних і нефункціональних вимог, проєктування та перевірки результату. Команда використовує його для узгодження роботи між зонами відповідальності, викладач — для оцінювання проєкту з дисципліни «Об'єктно-орієнтований аналіз і проєктування», а розробник, який долучається до проєкту, — для розуміння очікуваних можливостей і обмежень системи.

## 1.2 Product Scope

PicPick допомагає фотографу отримати від клієнта однозначний список кадрів для фінальної обробки. Сервіс замінює відбір через обмін файлами та переписку: клієнт переглядає захищені прев'ю й обирає фото без доступу до оригіналів. Мета продукту — спростити погодження вибору та зменшити ризик використання необроблених кадрів без дозволу фотографа.

До меж продукту входять:

- реєстрація і вхід фотографа за email і паролем, створення та керування галереями;
- завантаження оригіналів і фонове створення зменшених прев'ю з вотермаркою;
- створення та відкликання приватного посилання для клієнта з терміном дії; клієнт відкриває галерею за токеном без акаунта;
- перегляд прев'ю, додавання та зняття лайків до відправки вибору; після відправки вибір фіксується і більше не змінюється;
- отримання фотографом списку імен файлів обраних кадрів, фіналізація галереї та її видалення;
- припинення доступу після завершення терміну дії та автоматичне видалення прострочених даних.

До продукту **не входять** ретуш і фінальна обробка фото, передавання клієнту оригіналів, приймання оплати та довготривале архівне зберігання фото. Вотермарка захищає прев'ю, але сервіс не здійснює розрахунків між фотографом і клієнтом.

У межах навчального проєкту створюються проєктна документація та мінімальний працюючий прототип. Прототип охоплює основний сценарій: фотограф створює галерею й завантажує фото → система створює прев'ю → клієнт за посиланням відправляє вибір → фотограф бачить обрані кадри. Email-сповіщення, аналітика, моніторинг і розгортання у хмарі описуються в документації, але не реалізуються в прототипі; цільову архітектуру та спрощення прототипу слід розрізняти у відповідних розділах.

## 1.3 Definitions, Acronyms, and Abbreviations

Єдине джерело термінів, назв сутностей, статусів і скорочень — [глосарій проєкту](../glossary.md). Нижче наведено терміни, потрібні для читання вступу; повний перелік міститься в глосарії.

| Термін / скорочення | Значення |
|---|---|
| Фотограф (`Photographer`) | Користувач з акаунтом, який створює галереї й завантажує фото. |
| Клієнт (`Client`) | Замовник фотографій; переглядає прев'ю і обирає кадри. Акаунта не має. |
| Галерея (`Gallery`) | Набір фото з однієї зйомки, який фотограф показує одному клієнту. |
| Оригінал (`Photo`) | Необроблений файл, завантажений фотографом. Клієнту ніколи не показується. |
| Прев'ю (`PhotoPreview`) | Зменшена копія оригіналу з вотермаркою, яку бачить клієнт. |
| Вотермарка (`Watermark`) | Напівпрозорий напис на прев'ю, що захищає кадр від використання без оплати. |
| Посилання для клієнта (`ShareLink`) | Приватне посилання з секретним токеном, за яким клієнт відкриває галерею. |
| Токен (`Token`) | Випадковий секретний рядок у посиланні, що замінює клієнту логін. |
| Лайк (`Like`) | Позначка клієнта «цей кадр мені подобається». |
| Вибір (`Selection`) | Сукупність лайків клієнта в галереї. |
| Відправка вибору (`Submit selection`) | Дія клієнта, після якої вибір фіксується і більше не змінюється. |
| Фіналізація галереї (`Finalize`) | Дія фотографа, що закриває галерею для будь-яких змін. |
| Термін дії (`ExpiresAt`) | Дата, після якої галерея/посилання перестають бути доступними і підлягають видаленню. |
| SRS | Software Requirements Specification, специфікація вимог. |
| FR / NFR | Functional / Non-functional Requirement. |

## 1.5 Document Overview

Розділ 1 визначає мету SRS, межі PicPick, терміни та джерела; розділ 2 описує контекст продукту, основні можливості, обмеження й припущення. Подальші розділи деталізують акторів і сценарії використання, функціональні та нефункціональні вимоги, High-level Architecture й Identity Management. Перевірка вимог і додатки доповнюють специфікацію матеріалами для оцінювання відповідності реалізації погодженим вимогам.
