# 1. Introduction

## 1.1 Document Purpose

Ця специфікація вимог (SRS) визначає призначення, межі та очікувану поведінку PicPick — вебсервісу для спільного відбору фото фотографом і клієнтом. Документ узгоджує функціональні й нефункціональні вимоги та є основою проєктування, розробки й перевірки. Команда використовує його для узгодження роботи, викладач — для оцінювання проєкту з дисципліни «Об'єктно-орієнтований аналіз і проєктування», а розробник — для розуміння можливостей та обмежень системи.

## 1.2 Product Scope

PicPick замінює відбір через обмін файлами та переписку: клієнт обирає захищені прев'ю без доступу до оригіналів, а фотограф отримує список імен файлів для фінальної обробки. Мета — спростити погодження вибору та зменшити ризик використання необроблених кадрів без дозволу фотографа.

До меж продукту входять:

- реєстрація і вхід фотографа за email і паролем, створення, фіналізація та видалення галерей;
- завантаження оригіналів і фонове створення прев'ю з вотермаркою;
- створення та відкликання приватного посилання з терміном дії; доступ клієнта за токеном без акаунта;
- перегляд прев'ю, додавання та зняття лайків, відправка вибору, після якої він більше не змінюється;
- перегляд фотографом списку імен файлів обраних кадрів для фінальної обробки;
- припинення доступу після завершення терміну дії та автоматичне видалення прострочених даних.

До продукту **не входять** ретуш і фінальна обробка фото, передавання клієнту оригіналів, приймання оплати та довготривале архівне зберігання фото.

Навчальний проєкт включає документацію та мінімальний працюючий прототип основного сценарію: завантаження фото → створення прев'ю → відправка вибору клієнтом → перегляд результату фотографом. Email-сповіщення, аналітика, моніторинг і розгортання у хмарі описуються лише в документації; спрощення прототипу зазначаються у відповідних розділах.

## 1.3 Definitions, Acronyms, and Abbreviations

Єдине джерело термінів, сутностей, статусів і скорочень — [глосарій проєкту](../glossary.md). Нижче наведено основні; решта визначень доступна в глосарії.

| Термін / скорочення | Значення |
|---|---|
| Вибір (`Selection`) | Сукупність лайків клієнта в галереї. |
| Вотермарка (`Watermark`) | Напівпрозорий напис на прев'ю, що захищає кадр від використання без оплати. |
| Галерея (`Gallery`) | Набір фото з однієї зйомки, який фотограф показує одному клієнту. |
| Клієнт (`Client`) | Замовник фотографій; переглядає прев'ю і обирає кадри. Акаунта не має. |
| Оригінал (`Photo`) | Необроблений файл, завантажений фотографом. Клієнту ніколи не показується. |
| Посилання для клієнта (`ShareLink`) | Приватне посилання з секретним токеном, за яким клієнт відкриває галерею. |
| Прев'ю (`PhotoPreview`) | Зменшена копія оригіналу з вотермаркою, яку бачить клієнт. |
| Фотограф (`Photographer`) | Користувач з акаунтом, який створює галереї й завантажує фото. |
| FR / NFR | Functional / Non-functional Requirement. |
| SRS | Software Requirements Specification, специфікація вимог. |

## 1.5 Document Overview

Розділ 1 містить вступ; розділ 2 — огляд продукту, зокрема акторів у 2.4 і High-level Architecture у 2.7; розділ 3 — вимоги, зокрема Identity Management у 3.3.2; розділи 4–5 — перевірку вимог і додатки. Вимоги формулюються «Система повинна…», мають ID FR/NFR-1xx для зони A, 2xx для B, 3xx для C та пріоритет Must (обов'язково), Should (бажано) або Could (за можливості). Історія змін ведеться в Git: коміти зберігають автора, дату й опис, а PR — обговорення та схвалення за CONTRIBUTING.md.
