# API зони A: галереї

Контракт REST API для FR-103–108 і NFR-102 з [вимог зони A](../03-srs/zone-a-accounts.md). Назви сутностей і статусів — за [глосарієм](../glossary.md). Маршрути API відрізняються від сторінок Razor Pages у [sequence-діаграмі](../04-architecture/flow-zone-a.md).

## Обсяг заглушок

`GalleriesController` працює з тестовими метаданими в пам'яті одного процесу. Поточний Photographer фіксований; авторизації, PostgreSQL, фото, MinIO та фонового очищення немає. Створення, фіналізація й видалення змінюють тестові дані до перезапуску. Операції захищені локальним `lock`, який не замінює транзакцій або distributed-патернів цільової системи.

Формат помилок узгоджено з поточною [конвенцією #20, ПР #55](https://github.com/alonasaienko/picpick/pull/55): `application/problem+json`, поля `type`, `title`, `status`, `detail`, `instance`, `errorCode`, `traceId`; `errors` — лише для валідації, ключі в camelCase. Після мерджу конвенції джерелом є [conventions.md](conventions.md). ПР #55 ще на рев'ю; перед інтеграцією потрібно звірити фінальну редакцію.

## Ендпоінти

У цільовій системі кожен запит вимагає входу фотографа; власник береться з перевіреної ідентичності, а не з тіла запиту. У заглушках використано одного тестового власника. Усі відповіді успіху з тілом — JSON; час — ISO 8601 у UTC, ідентифікатори — UUID.

| ID | Метод і шлях | Вхід | Успішна відповідь | Помилки |
|---|---|---|---|---|
| A-101 | `POST /api/galleries` | JSON: `name`, `expiresAt` | **201**, Gallery зі статусом `Draft`, `photoCount: 0`; `Location: /api/galleries/{id}` | Спільні нижче; **415** `UNSUPPORTED_MEDIA_TYPE` — тіло не JSON; **422** `GALLERY_EXPIRES_AT_INVALID` — термін уже настав або перевищує 30 діб |
| A-102 | `GET /api/galleries` | Немає | **200**, масив власних Gallery, зокрема `[]`; новіші першими, за рівного `createdAt` — `galleryId` лексикографічно за зростанням | Спільні нижче |
| A-103 | `GET /api/galleries/{id}` | UUID у шляху | **200**, метадані власної Gallery | Спільні нижче; **404** `GALLERY_NOT_FOUND` — відсутня, видалена або чужа |
| A-104 | `POST /api/galleries/{id}/finalize` | UUID; тіла немає | **200**, `{ gallery, message }`; `Finalized`. Повтор: «Галерею вже фіналізовано» | Спільні нижче; **404** `GALLERY_NOT_FOUND`; **409** `GALLERY_NOT_FINALIZABLE` — `Draft`, `Processing` або `Expired` |
| A-105 | `DELETE /api/galleries/{id}` | UUID; тіла немає | **204**, без тіла; у заглушці видалено тестові метадані | Спільні нижче; **404** `GALLERY_NOT_FOUND` — зокрема після повторного DELETE |

Метадані Gallery: `galleryId`, `name`, `status`, `expiresAt`, `createdAt`, `photoCount`. Фото, вибір, email і секретні посилання не повертаються. Результат фіналізації містить ці метадані в `gallery` і поле `message`.

### Спільні помилки

| HTTP | errorCode | Коли виникає |
|---|---|---|
| 400 | `VALIDATION_FAILED` | Зламаний JSON, неправильний тип або UUID, відсутнє обов'язкове поле; назва після `Trim()` порожня чи довша за 100 символів. Також невідомий `demoError`. Поля перелічено в `errors`; для помилки всього тіла ключ `body` |
| 401 | `UNAUTHENTICATED` | Цільовий контракт: входу немає, cookie/сесія нечинні. У заглушках відтворюється лише через `demoError=401` |
| 403 | `GALLERY_ACTION_FORBIDDEN` | Цільовий контракт: автентифікований користувач не має дозволу на дію. Для поточного фіксованого Photographer природної гілки немає; лише демонстрація `demoError=403`. Чужа Gallery завжди дає 404 |
| 429 | `RATE_LIMIT_EXCEEDED` | Цільовий контракт: перевищено політику частоти; `Retry-After` — секунди. У заглушках лише `demoError=429`, `Retry-After: 30`; реальні ліміти реалізуються в [тасці #25](https://github.com/alonasaienko/picpick/issues/25) |
| 500 | `INTERNAL_ERROR` | Непередбачена помилка сервера; загальний текст без стектрейсу й внутрішніх даних. У заглушках `demoError=500` повертає готову відповідь, а не кидає виняток. Реальне глобальне перехоплення — [таска #23](https://github.com/alonasaienko/picpick/issues/23) |

Це перелік відповідей контролера; мережеві помилки й відповіді reverse proxy до нього не належать. Автоматичну валідацію зони A тимчасово оформлює локальний фільтр перед стандартним фільтром `[ApiController]`, щоб навіть зламаний JSON мав `errorCode`, `traceId` і безпечні повідомлення. Після #23 цей адаптер потрібно замінити спільною інфраструктурою без зміни контракту.

## Правила станів і валідації

- **400 / 422:** назва обов'язкова, містить 1–100 символів після видалення крайніх пробілів — схема DTO, тому 400. `expiresAt` обов'язковий і має бути датою з часовим поясом; значення порівнюється з поточним серверним часом: `now < expiresAt <= now + 720 годин`. Порушення цього правила — 422 з `errors.expiresAt`; зберігання в UTC.
- **403 / 404:** для чужої й відсутньої галереї однакові 404, `GALLERY_NOT_FOUND`, `title` і `detail`; відрізняються лише ідентифікатор запиту та шлях `instance`. Немає назви, власника або ознаки існування чужого ресурсу.
- **Фіналізація:** лише чинні `Ready`/`Shared` переходять у `Finalized`. Чинна `Finalized` повторно дає 200 без зміни даних за FR-106; повтор не є 409. `Draft`, `Processing`, `Expired` дають 409. Вибір клієнта не переводиться в `Submitted`.
- **Завершення терміну:** за `now >= expiresAt` метадані показують `Expired`, навіть якщо збережений статус був `Finalized`. До `expiresAt + 24 години` доступні тільки метадані. Після цієї межі заглушка прибирає їх при наступному читанні; це демонстрація контракту, а не реалізація фонового очищення FR-108.
- **Видалення:** власна Gallery видаляється в будь-якому статусі. Підтвердження діалогу належить UI. У цільовій системі успішне прийняття має негайно закривати доступ, а очищення пов'язаних даних і файлів — завершуватися окремо за FR-107. Заглушка не моделює сховище чи Worker; 204 означає видалення тільки тестових метаданих.

## Перевірка через Swagger UI

Запуск із кореня репозиторію:

```powershell
dotnet run --project src/webapp/WebApp.csproj --launch-profile http
```

Відкрити `http://localhost:5056/swagger`. XML-коментарі й `[ProducesResponseType]` показують описи, DTO та всі заявлені HTTP-коди. Поле `demoError` залишати порожнім для звичайного сценарію; воно діє лише в Development і не є частиною цільового API. В іншому середовищі непорожній `demoError` дає 400.

Тестові UUID мають формат `00000000-0000-0000-0000-000000000NNN`:

| NNN | Галерея при запуску |
|---|---|
| 101 | Власна `Draft` |
| 102 | Власна `Processing` |
| 103 | Власна `Ready` |
| 104 | Власна `Shared` |
| 105 | Власна `Finalized` |
| 106 | Власна `Expired`, термін минув годину тому |
| 199 | Чужа; повертає 404 й не потрапляє у список |
| 999 | Неіснуюча; та сама відмова, що й для 199 |

Перезапуск відновлює початкові тестові галереї. Нові UUID можна взяти з відповіді POST або списку.

| Перевірка | Дія у Swagger | Очікування |
|---|---|---|
| Створення й повторне читання | POST із назвою `"  Зйомка  "` і майбутнім `expiresAt` у межах 30 діб; GET за отриманим UUID | 201, `name: "Зйомка"`, `Draft`, нуль фото, коректний `Location`; GET 200 |
| Список | GET `/api/galleries` | 200; лише власні, правильне сортування, створена галерея присутня |
| 400 | POST `{}`; окремо порожня/довга назва, `expiresAt: "завтра"`, зламаний JSON або GET з `id=abc` | `VALIDATION_FAILED`, поле `errors` |
| 401 / 403 | GET списку з `demoError=401`, потім `403` | Відповідний статус і машинний код |
| 415 | POST створення з коректним JSON і `demoError=415` | `UNSUPPORTED_MEDIA_TYPE` (демонстрація) |
| 404 | GET, POST finalize й DELETE для UUID 199 та 999 | Однакові загальні відмови, жодних чужих даних |
| 409 | POST finalize для 101, 102 та 106 | `GALLERY_NOT_FINALIZABLE`, стан не змінено |
| Фіналізація й повтор | POST finalize для 103; повторити | Двічі 200; другий раз «Галерею вже фіналізовано» |
| 422 | POST з коректною назвою й `expiresAt: "2020-01-01T00:00:00Z"`; окремо дата далі 30 діб | `GALLERY_EXPIRES_AT_INVALID`, `errors.expiresAt` |
| 429 | GET списку з `demoError=429` | `RATE_LIMIT_EXCEEDED`, `Retry-After: 30` |
| 500 | GET списку з `demoError=500` | `INTERNAL_ERROR`, загальний текст, `traceId`, без стектрейсу |
| Видалення | DELETE власної галереї; GET і повторний DELETE | 204 без тіла, потім 404; галереї немає у списку |

Фактичний 415 можна відтворити HTTP-клієнтом, надіславши `text/plain` замість JSON; для Swagger є `demoError=415` лише в POST створення. Фактичний механізм авторизації, політики частоти та глобальну обробку винятків ці перевірки не підтверджують.

Автоматизована перевірка на запущеному Web App (PowerShell 7):

```powershell
./tests/webapp/zone-a-smoke.ps1
```

Скрипт перевіряє HTTP-контракт, валідацію, нормалізацію UTC, межі довжини назви, нерозкриття чужих галерей, переходи станів, видалення та описи OpenAPI. Нові тестові галереї прибираються; початкові Ready/Shared можуть залишитися Finalized до перезапуску.

Механізми ASP.NET Core: [автоматична валідація API](https://learn.microsoft.com/en-us/aspnet/core/web-api/?view=aspnetcore-8.0#automatic-http-400-responses), [XML-коментарі Swashbuckle](https://github.com/domaindrivendev/Swashbuckle.AspNetCore/blob/v6.6.2/README.md#include-descriptions-from-xml-comments).
