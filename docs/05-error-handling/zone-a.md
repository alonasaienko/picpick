# API зони A: галереї

Ендпоінти відповідають FR-103–108 і NFR-102 з [вимог зони A](../03-srs/zone-a-accounts.md). Формат помилок, обов'язкові поля та правила HTTP-кодів визначено в [конвенції помилок — conventions.md](conventions.md). Назви сутностей і статусів — за [глосарієм](../glossary.md).

## Обсяг заглушок

Контролер використовує одного фіксованого Photographer і тестові метадані в пам'яті. Зміни зберігаються до перезапуску; авторизацію, PostgreSQL, MinIO та фонове очищення не реалізовано. Ліміти запитів і глобальне перехоплення винятків належать таскам #25 і #23. Відповіді 401, 403, 429 і 500 тут імітуються.

## Ендпоінти

У цільовій системі власник визначається за входом фотографа. Відповіді успіху з тілом — JSON, час — ISO 8601 у UTC, ідентифікатори — UUID.

| ID | Метод і шлях | Вхід | Успішна відповідь | Помилки |
|---|---|---|---|---|
| A-101 | `POST /api/galleries` | JSON: `name`, `expiresAt` | **201**, Gallery зі статусом `Draft`, `photoCount: 0`; `Location: /api/galleries/{id}` | Спільні нижче; **415** `UNSUPPORTED_MEDIA_TYPE` — тіло не JSON; **422** `GALLERY_EXPIRES_AT_INVALID` — термін уже настав або перевищує 30 діб |
| A-102 | `GET /api/galleries` | Немає | **200**, масив власних Gallery, зокрема `[]`; новіші першими, за рівного `createdAt` — `galleryId` лексикографічно за зростанням | Спільні нижче |
| A-103 | `GET /api/galleries/{id}` | UUID у шляху | **200**, метадані власної Gallery | Спільні нижче; **404** `GALLERY_NOT_FOUND` — відсутня, видалена або чужа |
| A-104 | `POST /api/galleries/{id}/finalize` | UUID; тіла немає | **200**, `{ gallery, message }`; `Finalized`. Повтор: «Галерею вже фіналізовано» | Спільні нижче; **404** `GALLERY_NOT_FOUND`; **409** `GALLERY_NOT_FINALIZABLE` — `Draft`, `Processing` або `Expired` |
| A-105 | `DELETE /api/galleries/{id}` | UUID; тіла немає | **204**, без тіла; у заглушці видалено тестові метадані | Спільні нижче; **404** `GALLERY_NOT_FOUND` — зокрема після повторного DELETE |

Метадані Gallery: `galleryId`, `name`, `status`, `expiresAt`, `createdAt`, `photoCount`. Фото, вибір, email і секретні посилання не повертаються. Результат фіналізації містить ці метадані в `gallery` і поле `message`.

### Спільні помилки

| HTTP | errorCode | Коли виникає |
|---|---|---|
| 400 | `VALIDATION_FAILED` | Зламаний JSON, неправильний тип або UUID, відсутнє обов'язкове поле; назва після `Trim()` порожня чи довша за 100 символів. Також невідомий `demoError`. Поля перелічено в `errors`; для помилки всього тіла ключ `body` |
| 401 | `UNAUTHENTICATED` | Фотограф не ввійшов або сесія нечинна |
| 403 | `GALLERY_ACTION_FORBIDDEN` | Користувач має доступ до ресурсу, але не має дозволу на дію. Чужа Gallery завжди дає 404 |
| 429 | `RATE_LIMIT_EXCEEDED` | Перевищено ліміт запитів; `Retry-After` — секунди |
| 500 | `INTERNAL_ERROR` | Помилка сервера; загальне повідомлення й `traceId` за конвенцією |

## Правила станів і валідації

- **400 / 422:** назва обов'язкова, містить 1–100 символів після видалення крайніх пробілів — схема DTO, тому 400. `expiresAt` обов'язковий і має бути датою з часовим поясом; значення порівнюється з поточним серверним часом: `now < expiresAt <= now + 720 годин`. Порушення цього правила — 422 з `errors.expiresAt`; зберігання в UTC.
- **403 / 404:** чужа й відсутня галереї повертають однаковий 404, код і повідомлення без чужих даних — за конвенцією та NFR-102.
- **Фіналізація:** лише чинні `Ready`/`Shared` переходять у `Finalized`. Чинна `Finalized` повторно дає 200 без зміни даних за FR-106; повтор не є 409. `Draft`, `Processing`, `Expired` дають 409. Вибір клієнта не переводиться в `Submitted`.
- **Завершення терміну:** після `expiresAt` доступні лише метадані зі статусом `Expired` до очищення, не довше 24 годин. Заглушка прибирає їх при наступному читанні після цієї межі.
- **Видалення:** власну Gallery можна видалити в будь-якому статусі. У цільовій системі доступ закривається одразу, а пов'язані дані й файли очищуються за FR-107–108. У заглушці 204 означає видалення тестових метаданих.

## Перевірка через Swagger UI

Запустити `dotnet run --project src/webapp/WebApp.csproj --launch-profile http` і відкрити `http://localhost:5056/swagger`.

Swagger показує призначення кожного ендпоінту, умови помилок та `errorCode`. Описи задано через налаштування OpenAPI без коментарів у коді. У відповіді валідації `errors` пояснює конкретну проблему: відсутню назву, довжину, формат дати чи UUID.

Тестові UUID: `00000000-0000-0000-0000-000000000NNN`, де **101** — Draft, **102** — Processing, **103** — Ready, **104** — Shared, **105** — Finalized, **106** — Expired, **199** — чужа, **999** — неіснуюча галерея. Перезапуск відновлює початкові дані.

| Перевірка | Дія у Swagger | Очікування |
|---|---|---|
| Створення й повторне читання | POST із назвою `"  Зйомка  "` і майбутнім `expiresAt` у межах 30 діб; GET за отриманим UUID | 201, `name: "Зйомка"`, `Draft`, нуль фото, коректний `Location`; GET 200 |
| Список | GET `/api/galleries` | 200; лише власні, правильне сортування, створена галерея присутня |
| 400 | POST `{}`; окремо порожня/довга назва, `expiresAt: "завтра"`, зламаний JSON або GET з `id=abc` | `VALIDATION_FAILED`, поле `errors` |
| 401 / 403 | GET списку з `demoError=401`, потім `403` | Відповідний статус і машинний код |
| 415 | POST створення з коректним JSON і `demoError=415` | `UNSUPPORTED_MEDIA_TYPE` (демонстрація) |
| 404 | GET, POST finalize й DELETE для UUID 199 та 999 | Однакові загальні відмови, жодних чужих даних |
| 409 | POST finalize для 101, 102 та 106 | `GALLERY_NOT_FINALIZABLE`, стан не змінено |
| Фіналізація й повтор | POST finalize для 103; повторити | Двічі 200; другий раз «Галерею вже фіналізовано» |
| 422 | POST з коректною назвою й `expiresAt: "2020-01-01T00:00:00Z"`; окремо дата далі 30 діб | `GALLERY_EXPIRES_AT_INVALID`, `errors.expiresAt` |
| 429 | GET списку з `demoError=429` | `RATE_LIMIT_EXCEEDED`, `Retry-After: 30` |
| 500 | GET списку з `demoError=500` | `INTERNAL_ERROR`, загальний текст, `traceId`, без стектрейсу |
| Видалення | DELETE власної галереї; GET і повторний DELETE | 204 без тіла, потім 404; галереї немає у списку |

`demoError` працює лише в Development; для звичайних запитів його залишають порожнім. Фактичний 415 також виникає при надсиланні тіла `text/plain`. Автоматизована перевірка запущеного API: `./tests/webapp/zone-a-smoke.ps1` (PowerShell 7).
