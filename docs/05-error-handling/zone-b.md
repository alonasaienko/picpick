# API зони B: завантаження й обробка

Ендпоінти відповідають FR-201–FR-206 з [вимог зони B](../03-srs/zone-b-processing.md). Формат помилок, обов'язкові поля й правила HTTP-кодів визначено в [конвенції помилок](conventions.md).

## Обсяг заглушок

Файли перевіряються лише за сигнатурою вмісту й розміром (порожній, формат, ліміт МБ), але нікуди не зберігаються, а обробки немає. Можливість декодування не перевіряється: пошкоджений файл із правильною сигнатурою буде прийнятий, а помилку декодування в цільовій системі виявить Worker і поставить фото статус `Failed` (FR-205). Галереї — тестові дані зони A ([zone-a.md](zone-a.md)), фото — тестові дані в пам'яті до перезапуску. Авторизацію ще не реалізовано: 401 описано в документації та Swagger. Обмеження частоти працює: 429 повертає rate limiter за політиками з [конвенції, розділ 8](conventions.md#8-обмеження-частоти-запитів-rate-limiting).

## Ендпоінти

| ID | Метод і шлях | Вхід | Успішна відповідь | Помилки |
|---|---|---|---|---|
| B-201 | `POST /api/galleries/{galleryId}/photos` | `multipart/form-data`, поле `files`: до 50 файлів і до 1 ГБ | **200**, `accepted` (фото зі статусом `Uploaded`) і `rejected` (індекс, ім'я, `errorCode`, причина) | Спільні; **404** `GALLERY_NOT_FOUND`; **409** `GALLERY_NOT_EDITABLE`; **422** `PHOTO_ALL_FILES_REJECTED`, `PHOTO_BATCH_LIMIT_EXCEEDED`, `GALLERY_PHOTO_LIMIT_EXCEEDED` |
| B-202 | `GET /api/galleries/{galleryId}/progress` | UUID у шляху | **200**, `galleryStatus`, `total`, `ready`, `failed`, `inProgress` | Спільні; **404** `GALLERY_NOT_FOUND`; **409** `GALLERY_EXPIRED` |
| B-203 | `GET /api/galleries/{galleryId}/photos` | UUID у шляху | **200**, масив фото: `photoId`, `fileName`, `status`, `failureReason` (лише для `Failed`) | Спільні; **404** `GALLERY_NOT_FOUND`; **409** `GALLERY_EXPIRED` |
| B-204 | `POST /api/galleries/{galleryId}/photos/{photoId}/retry` | UUID галереї й фото | **200**, фото зі статусом `Uploaded` | Спільні; **404** `GALLERY_NOT_FOUND`, `PHOTO_NOT_FOUND`; **409** `PHOTO_NOT_FAILED`, `GALLERY_NOT_EDITABLE` |

### Спільні помилки

Однакові для всіх ендпоінтів зони B; реакцію клієнта на них описано один раз у [розділі 9 конвенції «Реакція клієнта»](conventions.md#9-реакція-клієнта). Чужа чи відсутня галерея (404 `GALLERY_NOT_FOUND`) належить кожному ендпоінту окремо й показана в прикладах.

| HTTP | errorCode | Коли виникає |
|---|---|---|
| 400 | `VALIDATION_FAILED` | Неправильний UUID; у запиті завантаження немає файлів |
| 401 | `UNAUTHENTICATED` | Фотограф не ввійшов |
| 429 | `RATE_LIMIT_EXCEEDED` | Перевищено ліміт запитів; `Retry-After` — секунди |
| 500 | `INTERNAL_ERROR` | Помилка сервера; загальний текст і `traceId` |

### Коди відхилення окремих файлів (у списку `rejected` або в `errors`)

| errorCode | Коли |
|---|---|
| `PHOTO_FILE_EMPTY` | Файл порожній |
| `PHOTO_FORMAT_NOT_SUPPORTED` | Вміст не є JPEG, PNG, HEIC чи підтримуваним RAW, навіть якщо розширення `.jpg` |
| `PHOTO_FILE_TOO_LARGE` | JPEG, PNG чи HEIC понад 30 МБ, RAW понад 150 МБ |

## Ключові рішення

- **Неправильний, завеликий чи порожній файл.** Окремий файл — не помилка всього запиту: він потрапляє в `rejected`, а решта приймається (200). Якщо відхилено всі файли — **422** `PHOTO_ALL_FILES_REJECTED`, причини за індексом у `errors["files[i]"]`. Так визначено в конвенції (виняток для пакетного завантаження).
- **Фіналізована галерея.** Завантаження в `Shared`, `Finalized` чи `Expired` — **409** `GALLERY_NOT_EDITABLE`: дані коректні, але стан галереї не дозволяє дію.
- **Повтор для вже обробленого фото.** **409** `PHOTO_NOT_FAILED`: повторити можна лише `Failed` (FR-206).
- **Забагато файлів занадто швидко.** Понад 50 файлів або 1 ГБ в одному запиті — **422** `PHOTO_BATCH_LIMIT_EXCEEDED`. Забагато запитів за короткий час — **429** `RATE_LIMIT_EXCEEDED` ([конвенція, розділ 8](conventions.md#8-обмеження-частоти-запитів-rate-limiting)). Запит понад ~1,01 ГБ сервер обриває ще до контролера.
- **Прострочена галерея.** Прогрес і список фото — **409** `GALLERY_EXPIRED`, без даних фото (FR-204). Метадані галереї доступні через API зони A.

## Приклади

Відповіді нижче отримано із запущеного застосунку (тестові дані з розділу «Перевірка через Swagger UI»); `traceId` і згенеровані `photoId` залишено як є. Скрізь клієнтський код спирається на `errorCode` і HTTP-статус, а не на текст `detail`: текст може змінитися, а код — ні.

### B-201 `POST /api/galleries/{galleryId}/photos`: завантажити пакет фото

**Запит.** Тіло — `multipart/form-data` з полем `files` (до 50 файлів і до 1 ГБ), тому показано через `curl`:

```bash
curl -X POST http://localhost:5056/api/galleries/00000000-0000-0000-0000-000000000101/photos \
  -F "files=@IMG_0001.jpg" -F "files=@IMG_0002.jpg" -F "files=@IMG_0003.jpg"
```

**Успіх:** `200 OK`; у тілі `accepted` — прийняті фото зі статусом `Uploaded`, і `rejected` — відхилені файли.

#### 200 з відхиленими файлами (часткове прийняття)

Запит: той самий; `IMG_0001.jpg` — JPEG, `IMG_0002.jpg` — текстовий файл із розширенням `.jpg`, `IMG_0003.jpg` — порожній.

```json
{
  "accepted": [
    {
      "photoId": "f827b605-373d-43fe-83a1-7f5284babce5",
      "fileName": "IMG_0001.jpg",
      "status": "Uploaded"
    }
  ],
  "rejected": [
    {
      "index": 1,
      "fileName": "IMG_0002.jpg",
      "errorCode": "PHOTO_FORMAT_NOT_SUPPORTED",
      "message": "Формат не підтримується: дозволено JPEG, PNG, HEIC і RAW (DNG, CR2, CR3, NEF, ARW, RAF)."
    },
    {
      "index": 2,
      "fileName": "IMG_0003.jpg",
      "errorCode": "PHOTO_FILE_EMPTY",
      "message": "Файл порожній."
    }
  ]
}
```

**Реакція клієнта.** Формально це успіх: прийняті фото збережено, галерея переходить у `Processing`, і сторінка починає опитувати прогрес (B-202). Але відхилені файли треба показати, інакше фотограф вирішить, що завантажилося все:
- над зоною завантаження — банер-попередження «Прийнято 1 з 3 файлів», під ним список відхилених: ім'я файлу й причина з `message`, згруповано за `errorCode` (наприклад, усі `PHOTO_FORMAT_NOT_SUPPORTED` разом). Список лишається, доки фотограф його не закриє;
- `index` вказує на позицію файлу в надісланому пакеті, тому браузер знаходить саме той файл, навіть якщо в пакеті два однакові імена;
- автоматично не повторювати: той самий файл знову буде відхилено. Фотограф може замінити файл і завантажити його окремо. Наступні пакети завантаження продовжують надсилатися.

#### 422 `PHOTO_ALL_FILES_REJECTED`

Запит: у галерею `…103` лише `IMG_0002.jpg` і `IMG_0003.jpg`.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.21",
  "title": "Дані не відповідають правилам",
  "status": 422,
  "detail": "Жоден файл не прийнято.",
  "instance": "urn:request:00-69d5f43163bfcae28c20fd2a1f7ecc74-2d930e30d968e938-00",
  "errorCode": "PHOTO_ALL_FILES_REJECTED",
  "traceId": "00-69d5f43163bfcae28c20fd2a1f7ecc74-2d930e30d968e938-00",
  "errors": {
    "files[0]": [
      "IMG_0002.jpg: Формат не підтримується: дозволено JPEG, PNG, HEIC і RAW (DNG, CR2, CR3, NEF, ARW, RAF)."
    ],
    "files[1]": [
      "IMG_0003.jpg: Файл порожній."
    ]
  }
}
```

**Реакція клієнта.** Відмінність від 200 з `rejected`: тут **нічого не збережено** і стан галереї не змінився, тому це помилка, а не попередження. Сторінка показує банер-помилку «Жоден файл із пакета не прийнято» і той самий список причин, але бере його з `errors`: ключ `files[i]` — індекс файлу в пакеті. Прогрес для цього пакета не запускається; інші пакети того самого завантаження надсилаються далі. Автоматичного повтору немає.

#### 422 `PHOTO_BATCH_LIMIT_EXCEEDED`

Запит: 51 файл в одному запиті.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.21",
  "title": "Дані не відповідають правилам",
  "status": 422,
  "detail": "Один запит може містити до 50 файлів сумарним обсягом до 1 ГБ.",
  "instance": "urn:request:00-9244f25e4301c3d639106d810f638cba-087f6a7b41e90b86-00",
  "errorCode": "PHOTO_BATCH_LIMIT_EXCEEDED",
  "traceId": "00-9244f25e4301c3d639106d810f638cba-087f6a7b41e90b86-00"
}
```

**Реакція клієнта.** Справний браузер сам ділить вибір на пакети до 50 файлів і 1 ГБ, тож ця помилка означає ваду в клієнтському коді. Браузер один раз автоматично ділить пакет навпіл і надсилає частини; якщо помилка повторюється — банер «Не вдалося завантажити, повідомте код» із `traceId`.

#### 422 `GALLERY_PHOTO_LIMIT_EXCEEDED`

Запит: 50 файлів у галерею, де вже 960 фото.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.21",
  "title": "Дані не відповідають правилам",
  "status": 422,
  "detail": "У галереї може бути до 1000 фото. Можна додати ще 40.",
  "instance": "urn:request:00-2b40167397ee8c7f658e753de7b34a61-7ebe48ad7792b416-00",
  "errorCode": "GALLERY_PHOTO_LIMIT_EXCEEDED",
  "traceId": "00-2b40167397ee8c7f658e753de7b34a61-7ebe48ad7792b416-00"
}
```

**Реакція клієнта.** Жоден файл пакета не збережено. Наступні пакети не надсилаються, бо їх теж буде відхилено. Банер-помилка: скільки фото ще можна додати; число браузер рахує сам як `1000 − total` з прогресу (B-202), а не розбирає текст `detail`. Автоматичного повтору немає: фотограф обирає менше файлів або видаляє зайві фото.

#### 409 `GALLERY_NOT_EDITABLE`

Запит: завантаження в галерею `…105` (`Finalized`).

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.10",
  "title": "Конфлікт стану ресурсу",
  "status": 409,
  "detail": "Галерея зі станом Shared, Finalized або Expired не дозволяє змінювати фото.",
  "instance": "urn:request:00-100368f2cc4a8a803cc61cbad4b4d828-4770bdf7a62f605e-00",
  "errorCode": "GALLERY_NOT_EDITABLE",
  "traceId": "00-100368f2cc4a8a803cc61cbad4b4d828-4770bdf7a62f605e-00"
}
```

**Реакція клієнта.** Стан галереї змінився, наприклад в іншій вкладці фотограф створив посилання для клієнта або фіналізував галерею. Браузер зупиняє всі ще не надіслані пакети, ховає зону завантаження й перезавантажує деталі галереї (`GET /api/galleries/{id}`). Подальша поведінка залежить від актуального статусу:
- **`Shared` або `Finalized`** — дозволений перегляд лишається: список фото й прогрес видно, банер «Галерею вже передано клієнту або закрито — додавати фото не можна»;
- **`Expired`** — сторінка прибирає список фото, імена файлів, причини помилок і прогрес, зупиняє опитування й показує лише метадані галереї, як у реакції на [409 `GALLERY_EXPIRED` для B-202](#409-gallery_expired) (FR-204, п.4).

Повтору немає.

#### 404 `GALLERY_NOT_FOUND`

Запит: завантаження в галерею `…999` (відсутня); чужа галерея дає таку саму відповідь.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.5",
  "title": "Ресурс не знайдено",
  "status": 404,
  "detail": "Галерею не знайдено або вона вам недоступна.",
  "instance": "urn:request:00-4b2c90ba504928ca19ff8c521b8ad5e3-28705600632f842c-00",
  "errorCode": "GALLERY_NOT_FOUND",
  "traceId": "00-4b2c90ba504928ca19ff8c521b8ad5e3-28705600632f842c-00"
}
```

**Реакція клієнта.** Галерею видалено або вона недоступна. Браузер зупиняє всі пакети й переходить до списку галерей зі сповіщенням-тостом «Галерею не знайдено». Повтору немає.

#### 400 `VALIDATION_FAILED` без файлів

Спільна помилка, але для B-201 має особливий вигляд: поле `errors.files`. Запит: `POST` без жодного файлу.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title": "Некоректний запит",
  "status": 400,
  "detail": "Додайте хоча б один файл.",
  "instance": "urn:request:00-60da1c06fc29c8cfa18290694606c034-4bdc7d9088eb5148-00",
  "errorCode": "VALIDATION_FAILED",
  "traceId": "00-60da1c06fc29c8cfa18290694606c034-4bdc7d9088eb5148-00",
  "errors": {
    "files": [
      "Файли відсутні."
    ]
  }
}
```

**Реакція клієнта.** Кнопка «Завантажити» неактивна, доки не вибрано файли, тож за справної сторінки цієї відповіді не буде. Якщо вона все ж прийшла, біля поля вибору файлів з'являється повідомлення з `errors.files`.

Спільні помилки (400, 401, 429, 500): див. [реакцію клієнта](conventions.md#9-реакція-клієнта). Після 429 браузер чекає `Retry-After` і повторно надсилає той самий пакет ([конвенція, розділ 8](conventions.md#8-обмеження-частоти-запитів-rate-limiting)).

### B-202 `GET /api/galleries/{galleryId}/progress`: прогрес обробки

**Запит:**

```
GET /api/galleries/00000000-0000-0000-0000-000000000103/progress HTTP/1.1
```

**Успіх:** `200 OK`, лічильники фото:

```json
{
  "galleryStatus": "Ready",
  "total": 10,
  "ready": 9,
  "failed": 1,
  "inProgress": 0
}
```

#### 409 `GALLERY_EXPIRED`

Запит: прогрес галереї `…106` (настав `ExpiresAt`).

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.10",
  "title": "Конфлікт стану ресурсу",
  "status": 409,
  "detail": "Термін дії галереї завершився, дані фото недоступні.",
  "instance": "urn:request:00-6f89f158517fb6a514f1e11702b53a1d-d760469c962299bc-00",
  "errorCode": "GALLERY_EXPIRED",
  "traceId": "00-6f89f158517fb6a514f1e11702b53a1d-d760469c962299bc-00"
}
```

**Реакція клієнта.** Опитування **зупиняється назавжди**: стан уже не зміниться. Сторінка перезавантажує деталі галереї й показує лише метадані зі статусом `Expired` (FR-105), без фото й прогресу.

#### 404 `GALLERY_NOT_FOUND`

Запит: прогрес галереї `…999`.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.5",
  "title": "Ресурс не знайдено",
  "status": 404,
  "detail": "Галерею не знайдено або вона вам недоступна.",
  "instance": "urn:request:00-3c8f0797ca2c595a0a6526009bac0ef7-dd9ec6d841eb8fed-00",
  "errorCode": "GALLERY_NOT_FOUND",
  "traceId": "00-3c8f0797ca2c595a0a6526009bac0ef7-dd9ec6d841eb8fed-00"
}
```

**Реакція клієнта.** Опитування зупиняється; перехід до списку галерей із тостом «Галерею не знайдено».

**Поведінка опитування при помилках.** Наступний запит надсилається лише після відповіді на попередній, тож запити не накладаються. Далі залежить від помилки:
- **409 `GALLERY_EXPIRED`, 404 `GALLERY_NOT_FOUND`** — опитування зупиняється, бо повтор нічого не змінить;
- **429** — опитування не зупиняється, а чекає `Retry-After`, потім продовжує зі звичайним інтервалом;
- **500 або обрив мережі** — діє загальна політика повторів із [конвенції, розділ 9](conventions.md#правило-повторів): до 3 автоматичних спроб із паузами 1, 2, 4 с і jitter ±50 %. Якщо всі спроби невдалі, опитування призупиняється, біля прогресу з'являється напис «Не вдалося оновити прогрес» і кнопка «Відновити оновлення». Після успішної відповіді (автоматичної спроби чи за кнопкою) опитування повертається до звичайного інтервалу 5 с.

Спільні помилки (400, 401, 429, 500): див. [реакцію клієнта](conventions.md#9-реакція-клієнта).

### B-203 `GET /api/galleries/{galleryId}/photos`: список фото зі статусами

**Запит:**

```
GET /api/galleries/00000000-0000-0000-0000-000000000102/photos HTTP/1.1
```

**Успіх:** `200 OK`, масив фото; `failureReason` заповнений лише для `Failed`. Перші два елементи:

```json
[
  {
    "photoId": "00000000-0000-0000-0000-000000000211",
    "fileName": "IMG_0011.jpg",
    "status": "Ready",
    "failureReason": null
  },
  {
    "photoId": "00000000-0000-0000-0000-000000000212",
    "fileName": "IMG_0012.jpg",
    "status": "Ready",
    "failureReason": null
  }
]
```

#### 409 `GALLERY_EXPIRED`

Запит: список фото галереї `…106`.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.10",
  "title": "Конфлікт стану ресурсу",
  "status": 409,
  "detail": "Термін дії галереї завершився, дані фото недоступні.",
```

### B-204 `POST /api/galleries/{galleryId}/photos/{photoId}/retry`: повторити обробку

**Запит:**

```
POST /api/galleries/00000000-0000-0000-0000-000000000103/photos/00000000-0000-0000-0000-000000000202/retry HTTP/1.1
```

**Успіх:** `200 OK`, фото повернуто в `Uploaded`, задача знову в черзі:

```json
{
  "photoId": "00000000-0000-0000-0000-000000000202",
  "fileName": "IMG_0002.NEF",
  "status": "Uploaded",
  "failureReason": null
}
```

**Захист від подвійного натискання.** Кнопка «Повторити» блокується одразу після натискання й показує індикатор, доки не прийде відповідь. Після 200 рядок фото отримує статус `Uploaded`, кнопка зникає, а опитування прогресу (B-202) поновлюється. Якщо другий запит усе ж дійде до сервера (дві вкладки), він отримає 409 `PHOTO_NOT_FAILED` і нічого не змінить. Сторінка не показує це як помилку, а оновлює стан фото за B-203 (див. нижче).

#### 409 `PHOTO_NOT_FAILED`

Запит: повтор для фото `…201`, яке вже має статус `Ready`.

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.10",
  "title": "Конфлікт стану ресурсу",
  "status": 409,
  "detail": "Повторити можна лише обробку фото зі статусом Failed.",
  "instance": "urn:request:00-0a90bd00640106335498244786827d91-618b6f21d4983dbb-00",
  "errorCode": "PHOTO_NOT_FAILED",
  "traceId": "00-0a90bd00640106335498244786827d91-618b6f21d4983dbb-00"
}
```

**Реакція клієнта.** Помилку не показувати: на момент запиту фото не було `Failed`, тобто вже оброблялося або було готове. Сторінка запитує актуальний список фото (B-203) і визначає стан кнопки «Повторити» лише за ним: для `Uploaded`, `Processing` і `Ready` кнопку прибирає; для `Failed` залишає доступною, якщо стан галереї дозволяє повтор (`Processing` або `Ready`), бо повторна обробка могла знову завершитися помилкою (FR-205). Автоматичного повтору немає.

#### 409 `GALLERY_NOT_EDITABLE`

Запит: повтор для фото `…221` у галереї `…104` (`Shared`).

```json
{
  "type": "https://tools.ietf.org/html/rfc9110#section-15.5.10",
  "title": "Конфлікт стану ресурсу",
  "status": 409,
  "detail": "Галерея зі станом Shared, Finalized або Expired не дозволяє змінювати фото.",
  "instance": "urn:request:00-f2e5b92fed41fc4457baf9b60716c62d-013a22db7047bfa8-00",
  "errorCode": "GALLERY_NOT_EDITABLE",
  "traceId": "00-f2e5b92fed41fc4457baf9b60716c62d-013a22db7047bfa8-00"
}
```

**Реакція клієнта.** Стан галереї змінився. Сторінка ховає всі кнопки «Повторити» й «Видалити» і перезавантажує деталі галереї. Далі — за актуальним статусом:
- **`Shared` або `Finalized`** — список фото й прогрес лишаються для перегляду, банер «Галерею вже передано клієнту або закрито»;
- **`Expired`** — дані фото й прогрес прибираються, опитування зупиняється, видно лише метадані, як у реакції на [409 `GALLERY_EXPIRED` для B-202](#409-gallery_expired).

Повтору немає.

## Перевірка через Swagger UI

Запустити `dotnet run --project src/webapp/WebApp.csproj --launch-profile http` і відкрити `http://localhost:5056/swagger`.

Тестові UUID мають вигляд `00000000-0000-0000-0000-000000000NNN`. Галереї: **101** Draft, **102** Processing, **103** Ready, **105** Finalized, **106** Expired, **999** відсутня. Фото в галереї 103: **201** Ready, **202** Failed.

| Перевірка | Дія | Очікування |
|---|---|---|
| Завантаження | POST photos для 101: один JPEG і один текстовий файл з розширенням `.jpg` | 200, JPEG у `accepted`, другий у `rejected` з `PHOTO_FORMAT_NOT_SUPPORTED` |
| 422 | POST photos для 103 лише з невалідними файлами | `PHOTO_ALL_FILES_REJECTED`, `errors["files[0]"]` |
| 409 | POST photos для 105 | `GALLERY_NOT_EDITABLE` |
| 404 | POST photos для 999 | `GALLERY_NOT_FOUND` |
| 400 | GET photos з `galleryId = abc` | `VALIDATION_FAILED` |
| Прогрес | GET progress для 103; для 106 | 200 з лічильниками; 409 `GALLERY_EXPIRED` |
| Повтор | POST retry для 103 / 201; потім для 103 / 202 | 409 `PHOTO_NOT_FAILED`; 200, фото `Uploaded` |
